# Librarian Backend Audit — July 2026

> Full-codebase audit of `backend/` (~47k lines Rust): bugs, security, performance, best practices,
> scope alignment against `docs/design.md`, and industry feature-gap analysis.
> Produced 2026-07-02 via six parallel deep-audit passes (media pipeline, security, torrent/sources/metadata,
> data layer, infrastructure/quality, scope alignment). All findings verified against source with file:line references.

## Executive summary

The codebase is **above-average for a self-hosted project** in architecture: a clean service manager with
dependency-ordered lifecycle, a genuinely enforced "no direct SQL" rule (zero raw SQL in `backend/src`,
mechanically verified by a contract test), real dataloader batching, Argon2 passwords, rustls everywhere,
and disciplined typed error handling. The torrent import path and the scanner/organizer are real and working
end-to-end.

The three big problems:

1. **Security is not deployment-ready** — two critical issues (JWT secret fallback, CORS) each independently
   yield full compromise, and the whole REST media surface is unauthenticated.
2. **Three core design invariants are unenforced in code** — manual-match protection doesn't exist, "never
   overwrite files" is breakable via races, and one scoring constant makes confident *wrong* auto-links that
   get baked onto disk.
3. **~40% of design.md is unimplemented** — most importantly the entire auto-download loop, which is arguably
   the product's central promise.

## 1. Critical — fix before anything else

| # | Issue | Where | Impact |
|---|-------|-------|--------|
| 1 | **Hardcoded JWT secret fallback** — server runs with a source-visible secret if env unset | `services/auth.rs:44` | Anyone can forge an admin token. Refuse to start without a secret |
| 2 | **CORS reflects any Origin with credentials** | `app.rs:42-48` | Any website a logged-in user visits can call the API with their cookie and read responses → account takeover. Use an explicit allowlist |
| 3 | **Episode score floor 0.65 + 0.05 wanted bonus = 0.70 auto-link threshold** | `library_scan.rs:4738`, `:4192`, `:5488` | Any file whose S/E numbers match a wanted episode auto-links to the *wrong show*, then auto-organize renames it on disk into the wrong folder. Same floor in `find_episode_match:2888` with **no threshold at all** |
| 4 | **"Never overwrite" TOCTOU races** — `exists()` check then `rename` (silently replaces on Linux) in organize; failed `hard_link` → `copy` in torrent import can **truncate the seeding source file** | `library_scan.rs:5871/5918`, `:6576/6606-6618` | Permanent data loss under concurrent organize/import (which the code itself does via `buffer_unordered`). Use `O_EXCL`-style exclusive create / `link`+error-on-exists, plus a per-target lock |
| 5 | **Manual matches have zero protection** — design Q9b (`match_type='manual'`, never overwritten) is entirely unimplemented | `matchMediaFile` mutation accepts `force:true` | User curation silently destroyed by any rescan/rematch |
| 6 | **Startup schema sync auto-executes `DROP TABLE`/column drops** | graphql-orm `migrations.rs:169,198` via `database.rs:1252` | Renaming a field = drop+add = silent data destruction on boot. Gate destructive steps behind confirmation/backup |
| 7 | **Unauthenticated media streaming + server always binds 0.0.0.0** (ignores `config.host`) | `api/media.rs`, `http_server.rs:86` | Anyone on the network streams the library; artwork/health endpoints also open |

## 2. High-priority bugs & reliability

### Media pipeline (`services/library_scan.rs`)

- Provider fallback creates shows/albums/audiobooks with **no confidence floor** (`:3577`, `:3782`, `:3892`) —
  garbage filenames create junk catalog entries (movies correctly use 0.78)
- Organize renames on disk **before** the DB update; if the update fails, next scan's reconciler
  **deletes the MediaFile row** (`:6927`, errors ignored). Also `relativePath` is never updated on organize —
  permanently stale (torrent import updates both — inconsistent)
- Reconciler can **mass-delete file records** if a network mount flaps mid-scan (root-exists checked only once
  at scan start `:1428`), and all candidate/reconcile queries silently truncate at **10,000 rows**
  (`:6872`, `:4261`, `:4332`, `:4432`) — >10k-file libraries mismatch silently
- `Metadata` match method is a **no-op** — identical code path to `Filename` (`:5457`); the 3-tier
  metadata-first contract (design Q6/Q7) is unimplemented, and matching fires before analysis completes anyway
  (`:1552`). Q7's original-name fallback chain is also collapsed (`:5306`)
- Candidate caches only invalidate at end-of-scan (`:1667`) — torrent imports run against stale wanted-lists
  indefinitely; `unmatch` and manual matches never invalidate
- One bad file aborts the whole scan (`?` at `:1490/:1503/:1515`), and a failing scan **hot-loops every 60s
  forever** (`last_scanned_at` never set on failure, `:896`)
- TV folder creation appends `" (year)"` but the organizer doesn't (`:8109` vs `:5672`) — creates empty
  duplicate trees every scan and protects the wrong folders
- Auto-organize safety guard **fails open** on error (`:3036-3049`); organize results in scan path discarded
  (`let _ =`); `tokio::fs::rename` has no EXDEV copy fallback (`:5918`)
- Torrent batch processing aborts on a single match error and writes hardcoded `processed=0, failed=1`
  (`:6061`, `:5970-5991`); `update_torrent_post_process_status` ignores its count params (`:6766`)
- Startup scanning-state reset has a paginate-while-mutating bug — skips every second page (`:926-989`)
- Scan worker has no panic isolation; a panic permanently kills the single worker and wedges
  `in_progress_scans` (`:1672`, `:1699`)
- `normalize_for_match` strips after the last `.` on **database titles** too — "Mr. Robot" → "mr" (`:2369`)
- Movie pattern with unknown year renders `"Title ()"` (`:8021`)
- Per-file GraphQL storm: `system_auth_user` does a `users` query on nearly every helper call (`:683`,
  `:1127`, `:1370`, `:2176`, collectors); one scanned file ≈ 6–10 GraphQL round-trips before matching starts;
  one global scan worker; blocking `WalkDir` on the runtime thread (`:1449`)

### Torrent / sources / metadata

- **Completed-torrent events can be silently dropped** — completion shares a lagging broadcast channel
  (cap 1024) with 1/sec-per-torrent progress events and imports synchronously inline
  (`torrent/service.rs:915-932`, `:1006`); `RecvError::Lagged` is logged and skipped; no reconciliation sweep.
  Give completion its own channel + a periodic "completed-but-unprocessed" DB sweep
- **No timeout on any indexer HTTP client** (all 5 definitions: `iptorrents.rs:99`, `1337x.rs:41`,
  `limetorrents.rs:40`, `thepiratebay.rs:56`, `yts.rs:74`); `search_all` has no deadline — one stalled tracker
  hangs every search and its GraphQL request forever
- **UPnP mapping expires after 1h and is never renewed** (`client.rs:275-298`, fired once at startup
  `service.rs:677`) — NAT'd deployments silently lose inbound connectivity
- `db_sync_loop` **deletes and re-inserts every torrent-file row every 10s** with full-table-scan lookups
  (`database.rs:774-963`, `find_torrent_by_info_hash` fetches the whole table `:857`) — huge SQLite write
  amplification, even idle; discarded bulk-delete result at `:795` can duplicate rows
- Search cache never populated (dead `insert`, `manager.rs:390`) and "rate limiting" is a 2-concurrency
  semaphore only — the pattern private trackers ban for
- 1337x and LimeTorrents results have **no magnet/link** (`1337x.rs:220`, `limetorrents.rs:206`) — visible
  but un-downloadable; only TPB and YTS produce grabbable releases
- MusicBrainz 1-req/s limiter is per-client-instance and instances multiply (`musicbrainz.rs:231`,
  new `MetadataService` per call at `library_scan.rs:2903`) — policy violation → IP ban risk
- IPTorrents: `parse_time_ago` fails on fractional ages → all publish dates become "now" (`:294-324`);
  search term not URL-encoded (`:222`); scraper fallback `table` selector fails silently to empty results
- Restart re-fires `Completed` for torrents still hash-checking at startup (`service.rs:610`); `remove` can
  leave zombie DB rows that **resurrect and re-download** on restart (`:302-335` + `restore_from_database`)
- Manual `process_completed_torrent` on a missing torrent reports false success (`:207-229`)
- `retry_async` retries permanent errors (401/404) and is off-by-one vs config name (`rate_limiter.rs:268`)
- OpenLibrary calls: fresh client per request, no timeout/rate-limit/User-Agent (`providers.rs:1520`, `:1826`)
- `MetadataSettings::load` does ~8 full `app_settings` scans per provider request (`settings.rs:40`);
  metadata cache table grows unbounded
- Artwork fetch uses global no-timeout client (`artwork.rs:77`); cached artwork never refreshed when
  source URL changes (`:60-74`)
- `sync_show_episodes_from_tvmaze` is sequential per-episode and aborts whole sync on first failure
  (`providers.rs:2567-2712`)

### Data layer (graphql-orm + wiring)

- `hasNextPage` **hardcoded `false`** in the generated list path (graphql-orm `query.rs:695`) — Relay-style
  pagination stops at page 1
- **No limit cap** — omitting `page` renders no `LIMIT` (`query.rs:398`); `parse_pagination_args` accepts
  `first: 1000000` (`pagination.rs:167`) — any member can pull whole tables (DoS)
- Relation pagination is fake: all child rows fetched, paged in memory (`loaders.rs:233-301`). Dataloader
  batching is real (no classic N+1), but the cost moved to memory
- **SQLite runs without WAL**, default 10-conn pool, default 5s busy timeout (`db/mod.rs:29-44`) — scans block
  reads; concurrent writers → `SQLITE_BUSY` → GraphQL 500s
- **Almost no FK indexes** — only shows/episodes declare any; `media_files`, `tracks`, `chapters`,
  `torrent_files` etc. have unindexed `library_id`/`show_id`/`album_id` — every relation batch and cascade
  delete is a table scan
- Subscription `filter` argument is **ignored** (generated `_filter`); bulk mutations emit per-row events into
  a 256-cap broadcast → silent event loss (`Lagged` → `None`), UI drift
- `ContentStatus` computation is a stub — discards its inputs; `Playing`/`Paused`/`Downloading` unreachable
  (`entities/common.rs:51-70`)
- Library-delete hook: ~1,600+ statements per 800-show library inside one write transaction
  (`database.rs:311-420`) — correct atomicity, app-stalling shape
- Schema stages are hand-bumped; forgetting a stage = silent schema drift between fresh and existing DBs
  (`database.rs:135-147`)
- Latent: row-policy list path fetches entire tables then filters per-row in memory (dormant — no policy
  installed yet)
- Cursors are base64 offsets (unstable under concurrent writes, O(offset) deep pages); `COUNT(*)` on every
  list query regardless of selection
- Local `macros/` crate (3,231 lines) is a divergent, buggier duplicate of the ORM macros — unused (contract
  test forbids it) but a trap; `batch_load.rs` keys relations by primary key (wrong for one-to-many)
- Raw sqlx error text (SQL fragments, table names, paths) forwarded to GraphQL clients (`database.rs:265`)
- Doc drift: `AGENTS.md` whitelists `db/schema_sync.rs`, which doesn't exist

### Infrastructure

- **No SIGTERM handling** (`main.rs:222` waits on ctrl_c only) — Docker/systemd stops are never graceful;
  `stop_all()` never runs; librqbit session not flushed
- `panic='abort'` release profile + runtime unwraps (`media.rs:167,188`, per-call `Regex::new().unwrap()` at
  `library_scan.rs:7959`, `rate_limiter.rs:60,162`) = one panic kills the whole server
- Blocking `WalkDir` on the async runtime (`library_scan.rs:1449`, `:7064`) with workers clamped to 2–8 —
  a slow NFS walk starves the HTTP server (contrast: cast service does `spawn_blocking` correctly)
- `app_log` grows without bound (no retention anywhere); log "batch" flush is row-by-row inserts every 2s
  with a self-amplifying failure loop (`logging.rs:263-319`); a global `std::sync::Mutex` serializes every
  tracing event in the process (`main.rs:98`, `logging.rs:48`)
- HTTP server shutdown abandons in-flight requests — no `with_graceful_shutdown` (`http_server.rs:94-121`)
- Config parse errors silently swallowed (`config/mod.rs:126-146`); `HOST` accepted but never used for binding
- `opt-level='z'` on a CPU-heavy workload (piece hashing, image decode, fuzzy matching); maximal build times
- Nondeterministic service start order among dependency-independent peers (`manager.rs:492-507`)

## 3. Authorization model (biggest architectural security gap)

The RBAC plan (`docs/rbac-implementation-plan.md`) is documented but ~80% unbuilt:

- **Admin/Member only** (no Guest); role-level entity policies only (`graphql/policy.rs:42-52`)
- **No per-user ownership scoping anywhere** — any member can read/modify/delete any other user's playback
  progress, notifications, cast sessions — and shared entities (libraries, movies) are member-writable/deletable
- **Registration is open** — the entire `InviteToken` entity has **no redemption path** (empty custom ops,
  `register()` never consumes a token); no login rate limiting or lockout
- GraphQL **introspection + GraphiQL always on** (`graphql/service.rs:103`, no `.disable_introspection()`);
  **no depth/complexity limits**
- Refresh token returned in the response body alongside the HttpOnly cookie (negates the cookie protection);
  `Secure` flag depends solely on a spoofable `x-forwarded-proto` header; `SameSite=Lax`
- Source-credential AES-256-GCM key stored **in the same SQLite file as the ciphertext**
  (`sources/service.rs:64-74`, `app_settings.sources_encryption_key`) — encryption at rest is obfuscation;
  short keys are silently zero-padded (`encryption.rs:29`)
- SSRF: member-writable `poster_url` + `recacheMovieArtwork` → server fetches attacker-chosen internal URLs
  (`artwork.rs:77`); no host/scheme allowlist
- Unauthenticated `/api/health` leaks filesystem/network config; `/api/artwork/stats` open
- Dead-but-dangerous: `api/filesystem.rs` handlers (unauthenticated arbitrary directory list/create) are
  commented out — delete or gate before ever re-enabling; `api/torznab.rs` parses but never validates `apikey`

**The good foundations**: Argon2 via agql-auth, refresh-token rotation with a real store, no format!-built
SQL anywhere, ffprobe invoked via `.arg()` (no shell → no command injection), filesystem/backup mutations
correctly admin-gated, admin policies on users/sources/settings/tokens.

streaming with HTTP range support, Chromecast (full CASTV2 control + mDNS), 5 built-in indexers with
encrypted credentials, Ollama-assisted matching, TUI dashboard, single-binary frontend embed.

|----------|---------|
| **Auto-download for wanted items** | ❌ **Doesn't exist.** `src/jobs/` isn't there; `wanted`/`auto_download` flags are bookkeeping nothing consumes. The acquire loop — the core promise — is absent |
| Quality profiles / upgrade detection | ❌ Nothing — not even the `quality_status` column design.md describes (Phase 4 / Q23–Q26 entirely unimplemented) |
| Usenet | 👻 Entities + settings UI, **no NNTP/NZB client** — users can configure servers nothing uses |
| RSS polling | 👻 Entities only (with all the poll-bookkeeping columns), no poller — matches "planned" doc status |

## 6. Industry gap analysis — features peers have that Librarian doesn't

Compared against Sonarr/Radarr/Lidarr (acquisition), Prowlarr/Jackett (indexers), Jellyfin/Plex (playback),
Audiobookshelf (audiobooks).

### Tier 1 — core-scope gaps (finish existing promises first)

1. **Auto-download loop** — the wanted→search→grab→import monitor. Without it Librarian is a scanner+player,
   not an automation tool. Single highest-value feature
2. **Quality profiles + upgrade automation** — the *arr killer feature: profile per library/show, cutoff,
   upgrade-until, release scoring. The schema captures resolution/HDR already; the decision layer is missing
3. **Torznab/Newznab client support** — 5 hardcoded scrapers (2 of which can't produce download links) vs.
   the entire Prowlarr/Jackett indexer ecosystem for free. One generic Torznab source definition unlocks
   hundreds of indexers and is far cheaper than maintaining scrapers
4. **HLS transcoding** — without it, playback fails on any codec the browser can't decode (HEVC/DV rips).
   Even a simple ffmpeg remux path covers most cases

### Tier 2 — table stakes in this space

5. **Failed-download handling + blocklist** — *arr apps auto-blocklist a bad release and grab the next one
6. **Webhooks / notification integrations** (Discord, Telegram, ntfy, generic webhook) — current notifications
   are in-app poll-only
7. **Calendar view** (upcoming episodes/releases) — `schedule_cache` already exists; surface it
8. **Subtitle downloading** (OpenSubtitles/Bazarr-style) + extraction to WebVTT
9. **Server-side watch-state / resume** — `playback_progress` is client-honor-system today; add
   "continue watching"
10. **Health check system** — first-class "indexer unreachable", "disk almost full" (design Q43's TODO),
    "mount missing" items; notification plumbing already exists
11. **Seeding controls** — ratio/time limits per tracker; design promises "seeding control", none exposed

### Tier 3 — differentiators for later

12. Import lists (Trakt/TMDB lists → auto-add wanted)
13. Trickplay previews / chapter thumbnails (ffprobe chapters already captured)
14. Hardware-accelerated transcoding (VAAPI/NVENC/QSV)
15. Stable public API + API keys for third-party apps/scripts (no non-cookie auth story today)
16. Podcasts (adjacent to the audiobook pipeline; Audiobookshelf's growth feature)

### Differentiators to protect

Single-binary + embedded frontend + built-in torrent client (nobody in the *arr/Jellyfin world does all
three), entity-macro ORM with live subscriptions, Ollama-assisted matching, TUI dashboard.

## 7. Suggested priority order

1. **Week-one security patch**: mandatory JWT secret, CORS allowlist, auth on `/api/media` + artwork,
   honor `config.host`, disable introspection/GraphiQL in release, cap GraphQL page limits
2. **Pipeline safety**: kill the 0.65 episode floor, add provider-fallback thresholds, implement
   `match_type='manual'` protection, atomic no-clobber file ops + per-torrent lock,
   DB-update-before-rename in organize
3. **Data durability**: WAL + busy_timeout + FK indexes; gate destructive schema sync; fix `hasNextPage`;
   dedicated completion channel + reconciliation sweep
4. **Ownership scoping** in the ORM policy layer (per-user filtering) + invite redemption — prerequisite
   for calling it multi-user
5. **Then features**: auto-download loop → quality profiles → Torznab client → HLS. That sequence turns the
   remaining design.md promises into the feature set users expect from the *arr+Jellyfin stack
6. **Cleanup pass**: delete dead files/deps (`provders.rs`, `api/torznab.rs`, `md5`, `native-tls`,
   `serde_yaml`, `crc32fast`, `serde_bencode`, unused `tokio-cron-scheduler`), remove `#![allow(dead_code)]`,
   add `cargo audit`/`cargo machete` to lint, SIGTERM handling, app_log retention
